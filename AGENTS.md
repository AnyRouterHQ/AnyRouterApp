# AGENTS.md — AnyRouter iOS/iPadOS app

Contract for every agent working in this repo (Claude Code, Codex, Cursor, others).
`CLAUDE.md` points here. Edit this file, not `CLAUDE.md`.

## Goal

A native SwiftUI chat app for iPhone and iPad, named **AnyRouter**, that looks and behaves like
the Atomic Chat mobile app (rebranded) and chats with three model sources:

1. Apple Foundation Models (on device)
2. Local Hugging Face models (GGUF via llama.cpp, and MLX), with a configurable catalog
3. AnyRouter cloud models, after sign-in with AnyRouter OAuth

`PLAN.md` is the single source of truth for scope, decisions, lanes, and status.

## Start of every session

1. Read `PLAN.md` in full. Find your lane and its unchecked tasks.
2. Read the reference code your task points at (paths below). Do not guess.
3. Work on your lane branch in your own git worktree (see Workflow). Never edit another lane's folders.

## Open source

This repo is **public** (Apache-2.0). Everything you commit, every PR, issue, comment, branch name, and Actions log is public.

- Never commit secrets, API keys, tokens, signing files, Team IDs, device UDIDs, personal paths (`/Users/...`), internal hostnames, IPs, or private repo names.
- Local overrides go in `Config/Local.xcconfig` and `.env` (both gitignored). Copy from `Config/Local.xcconfig.example` and `.env.example`.
- CI runs gitleaks on every PR. Run `gitleaks git .` before you push if you have it.

## Hard rules

- **No local builds on the maintainer's Mac** (agents running there). It has no Xcode and runs many agents at once. Do not run `xcodebuild`, `swift build`, `node`, `pnpm`, `npm`, `bun`, `tsc`, or docker. **CI is the gate.** Contributors with Xcode 26 may build locally; agents push, then read the run with `gh run watch` / `gh run view --log-failed`. Say plainly in your report that local checks were skipped.
- Swift 6, iOS/iPadOS **26.0** minimum (Foundation Models needs it), SwiftUI + Observation + SwiftData. No UIKit views unless SwiftUI cannot do the job.
- Project is generated by **XcodeGen** from `project.yml`. Never commit `*.xcodeproj`. New files are picked up by folder globs, so do not edit `project.yml` unless your lane owns it (lane A) or you add a package dependency (say so in the PR).
- Follow the data contract in `PLAN.md` § Contract. Changing it is a PR to `Core/` that lane A reviews; do not fork the types.
- Secrets: OAuth keys go to the Keychain only. Never log keys, tokens, or prompts. No secrets in the repo; signing material lives in GitHub Actions secrets.
- Keep it small. No speculative abstractions, no feature beyond the task. Comments only where the why is not obvious.

## Workflow

```bash
cd AnyRouterApp   # your main checkout
git fetch origin
git worktree add ../AnyRouterApp-wt-<lane> -b lane/<lane>-<topic> origin/main
cd ../AnyRouterApp-wt-<lane>
# edit, commit small semantic commits: feat(local): add GGUF downloader
git push -u origin HEAD
gh pr create --fill --base main   # ready for review, never draft
gh pr checks --watch              # CI must be green
```

- Commits: `type(scope): subject`, simple English. Scopes: `app`, `core`, `design`, `ui`, `auth`, `remote`, `apple`, `local`, `ci`, `docs`.
- PR body headings, in order, 40 lines max: `Why`, `What changed`, `Scope`, `Tradeoffs`, `Verification`.
- Merge with `gh pr merge --squash --delete-branch` once CI is green and the PR touches only your lane's folders. Then remove your worktree.
- Rebase on `origin/main` before pushing if main moved.

## Updating PLAN.md (required)

PLAN.md is how lanes and humans see progress. In the same PR as the work:

- Tick the task box `- [x]` and add the PR number: `- [x] A3 CI workflow (#4)`.
- Add one line to § Status log: `2026-11-26 lane-B: OAuth sign-in works in simulator CI test (#7)`.
- New finding, blocker, or decision → § Open questions or § Decisions. Do not bury it in a PR.
- Only touch your lane's section plus the log, questions, and decisions sections, so PLAN.md merges cleanly.

## Definition of done for a task

- CI green on the PR (build for iOS Simulator + unit tests).
- Behavior covered by a test where it is logic (parsing, catalog, SSE, PKCE, prompt building). UI is checked by SwiftUI previews and screenshots later.
- PLAN.md updated as above.
