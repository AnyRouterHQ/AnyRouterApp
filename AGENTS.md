# AGENTS.md — AnyRouter iOS/iPadOS app

Contract for every agent working in this repo (Claude Code, Codex, Cursor, others).
`CLAUDE.md` points here. Edit this file, not `CLAUDE.md`.

## Goal

A native SwiftUI chat app for iPhone and iPad, named **AnyRouter**, that looks and behaves like
the reference mobile chat design and chats with three model sources:

1. Apple Foundation Models (on device)
2. Local Hugging Face models (GGUF via llama.cpp, and MLX), with a configurable catalog
3. AnyRouter cloud models, after sign-in with AnyRouter OAuth

`PLAN.md` is the single source of truth for scope, decisions, lanes, and status.

2. Read the code and docs your task points at. Do not guess.

## Hard rules

- **No local builds on the maintainer's Mac** (agents running there). It has no Xcode and runs many agents at once. Do not run `xcodebuild`, `swift build`, `node`, `pnpm`, `npm`, `bun`, `tsc`, or docker. **CI is the gate.** Contributors with Xcode 26 may build locally; agents push, then read the run with `gh run watch` / `gh run view --log-failed`. Say plainly in your report that local checks were skipped.
- Swift 6, iOS/iPadOS **26.0** minimum (Foundation Models needs it), SwiftUI + Observation + SwiftData. No UIKit views unless SwiftUI cannot do the job.
- Project is generated by **XcodeGen** from `project.yml`. Never commit `*.xcodeproj`. New files are picked up by folder globs, so do not edit `project.yml` unless your lane owns it (lane A) or you add a package dependency (say so in the PR).
- Follow the data contract in `PLAN.md` § Contract. Changing it is a PR to `Core/` that lane A reviews; do not fork the types.
- Secrets: OAuth keys go to the Keychain only. Never log keys, tokens, or prompts. No secrets in the repo; signing material lives in GitHub Actions secrets.
- Keep it small. No speculative abstractions, no feature beyond the task. Comments only where the why is not obvious.

## Design rule: native first

The app should look and behave like a stock iOS 26 app. Before you build a custom view, use the system one:

- Lists and settings: `List` / `Form` with `.insetGrouped`, `Section` headers, `Label` + SF Symbols, `NavigationLink`, `Toggle`, `Picker`. No hand-made cards or row chrome.
- Navigation: `NavigationStack` / `NavigationSplitView`, toolbar items with system buttons (`.close`, `.confirm` roles), `.searchable`, `Menu`, `ShareLink`, sheets with `presentationDetents`. No custom circle buttons, nav bars or search fields.
- Look: system fonts (`.body`, `.headline`, …, so Dynamic Type works), semantic colors (`.primary`, `.secondary`, `Color(.systemGroupedBackground)`), and one app tint (the accent color) set once. No per-icon tinting and no custom palettes for chrome.
- Sizes follow the HIG: every tappable control has at least a 44×44pt hit area. Use system sizing (`.controlSize(.large)` for primary buttons, `.imageScale(.large)` or the default toolbar symbol size), no hard-coded small frames like 32pt. UI tests run `performAccessibilityAudit()`, which fails on small hit regions, clipped text and low contrast.
- Liquid Glass comes from the system components. Add `.glassEffect` only on custom floating controls (the composer, the model pill), never on content.
- A custom view needs a reason the system one can't meet, written in one comment.
- CI enforces this with `scripts/native-ratchet.sh`: no file may gain custom-UI patterns (ARColor, .ar fonts, hand-drawn shapes, custom chips/buttons/search). After converting a file, run `scripts/native-ratchet.sh --update` and commit the lower baseline. Reference: Apple HIG (developer.apple.com/design/human-interface-guidelines) and the WWDC25 Liquid Glass sessions.

## Workflow (trunk-based)

Everyone commits to `main`. No pull requests for agent work (outside contributors may still open PRs).

```bash
cd AnyRouterApp                      # your own worktree or clone; one per agent
git pull --rebase origin main
# work in large, coherent chunks; commit often locally
git commit -m "feat(local): add GGUF downloader"
git pull --rebase origin main        # resolve conflicts yourself, you know your code
git push origin HEAD:main            # retry pull --rebase + push if rejected
```

- **Builds:** every push to `main` builds on macOS. A running build always finishes; only the newest waiting push queues behind it (pushes in between are skipped), so pushes are cheap. Put `[skip ci]` in the commit message for docs-only or work-in-progress pushes you don't need built. Docs-only changes skip the macOS build automatically.
- **Runner budget:** the org has 5 macOS runners. `main` CI comes first. Don't dispatch CI, screenshots, perf or verify runs on your own branches to check work; push to main and read its build. Dispatch perf/screenshots/verify on main only when you need their output, one at a time.
- **Red main:** if the build on your commit fails, fixing it is your first job, as a new commit. Never revert someone else's work without telling the manager.
- **Review:** a reviewer agent reads commits since the `review/last` tag, pushes fix commits, then moves the tag. Don't wait for review.
- **Releases:** production builds come from tags (`v0.1.0`), which run the TestFlight workflow. Only the operator decides when to tag.
- Commits: `type(scope): subject`, simple English. Scopes: `app`, `core`, `design`, `ui`, `auth`, `remote`, `apple`, `local`, `mcp`, `ci`, `docs`.
- Never force-push `main`. Never rewrite published history.

## Testing rules learned the hard way

- The CI Simulator build is unsigned and has no working Keychain. Tests use the in-memory credential store (InMemoryBacking / a fake store), never the real Keychain.
- The coverage gate counts each `?? fallback` autoclosure as a line. Rewrite unreachable fallbacks (`if let`, a helper) or test them.
- Swift file names must be unique across the repo, and no type may be named like a Swift Testing type (`Attachment`, `Test`, `Tag`, `Issue`). `scripts/source-check.sh` checks both on every push.
- Watch raw strings in fixtures: `#"…"#` ends at the first `"#` inside it. Use `##"…"##`.
- Never push code that you have not at least type-checked in your head to main as "wip". Red main blocks every lane.
